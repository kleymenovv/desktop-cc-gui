# Общая работа над проектом в CC GUI и Paperclip

Статус: первый этап реализован в исходниках, 2026-11-17; сборка и публикация отложены по просьбе пользователя. Готовы отдельные вкладки проектов с четырьмя разделами, привязка Paperclip, собственные сессии, просмотр реальных запусков задач, локальные файлы и существующий Git. Передача диалога команде, сохраняемые связи отдельной задачи с личной сессией и передача управления runtime ниже остаются следующими этапами.

## Цель

Пользователь открывает проект и в одном месте видит собственные диалоги, задачи автономной команды, выполняемые действия, изменения файлов и запросы внимания. Он может сам внести правки и передать задачу команде без повторного объяснения контекста и поиска между двумя разделами приложения.

## Что уже есть в исходниках

- CC GUI хранит рабочие папки и сессии: `src/features/chat/store/workspaces.ts`, `sessions.ts`, `persistence.ts`. В интерфейсе уже есть файлы, Git и операции с worktree.
- Проект Paperclip содержит `id` и `primaryWorkspace.cwd`; задача содержит ссылку на проект. Проекты и задачи уже доступны через `src/features/paperclip/api.ts` и `PlanningPanels.tsx`.
- Текущая интеграция показывает задачу, обсуждение и публичные события запусков (`IssueActivity.tsx`). Она не превращает внешний запуск в управляемую обычную сессию CC GUI.
- Paperclip самостоятельно исполняет Codex через адаптер. В соседнем репозитории `packages/adapters/codex-local/src/server/execute.ts` возобновление зависит от реальной runtime-сессии, рабочей папки и execution identity. Совпадение имени проекта или модели не доказывает совместимость сессий.
- Проекция запусков в `src-tauri/src/paperclip/activity.rs` намеренно не передаёт invocation context и сырые логи. Ради новой навигации эту границу расширять не требуется.

## Общая модель

Общая точка входа — существующий проект и его рабочие папки. Задача отвечает за цель, исполнителя, статус и приёмку. Сессия отвечает за общение и конкретную работу. У задачи может быть несколько сессий и запусков: обсуждение с пользователем, реализация агентом, проверка. Обычная сессия может оставаться без задачи.

Данные задачи остаются в Paperclip, данные обычного диалога — у CC GUI и соответствующего движка. Связи хранят идентификаторы, а интерфейс собирает общее представление; копировать переписку в обе базы и синхронизировать две независимые версии задачи не нужно.

Связь проекта использует идентичность локального подключения Paperclip, companyId, projectId и проверенную локальную папку. Название не является ключом. Путь используется как подсказка для привязки, а не как доказательство: несколько проектов могут использовать один репозиторий, а удалённый cwd не является локальной папкой.

## Как это выглядит

В боковом меню остаётся привычный список рабочих проектов. Внутри проекта доступны:

- **Задачи** — общая очередь команды, исполнители, блокировки, согласования.
- **Сессии** — личные диалоги и связанные с задачами рабочие сессии, с обозначением источника и режима управления.
- **Файлы и Git** — существующие инструменты CC GUI для выбранной рабочей папки или worktree.
- **Активность** — события проекта и запросы внимания с переходом к исходной задаче или сессии.

«Команда агентов» остаётся общим обзором нескольких проектов и настройкой команды. «Доска агентов» может оставаться сводкой работы по проектам; её не следует выдавать за ещё одно место хранения задач. Переносить или удалять эти входы до появления общего экрана не нужно.

## Основные сценарии

### Самостоятельная разработка

Открыть проект → «Новая сессия» → работа с кодом через обычный CC GUI. Создавать задачу ради небольшого вопроса не требуется. При необходимости пользователь связывает сессию с существующей задачей.

### Передача работы команде

Из диалога → «Передать команде» → просматриваемый черновик задачи: цель, критерии готовности, рабочая папка, выбранный контекст. Пользователь проверяет исполнителя и содержимое, затем отправляет. Полный диалог, скрытые инструкции, локальные вложения и секреты автоматически не копируются.

Для повторного нажатия / сетевого повтора сохраняется идентификатор операции. После неоднозначного ответа интерфейс проверяет результат, а не создаёт следующую задачу вслепую. После создания появляется двусторонняя связь: задача из диалога и диалог из задачи.

### Участие разработчика в задаче

Из задачи → «Открыть рабочую папку» или «Обсудить в CC GUI». Новая сессия получает выбранное описание задачи и доступный публичный результат, обозначается как отдельная сессия, связанная с задачей. Само открытие не отправляет сообщение модели и не меняет исполнителя.

«Взять в работу» — отдельное действие. Пока Paperclip выполняет задачу, продолжение того же runtime требует поддерживаемой остановки / передачи и подтверждённого завершения предыдущего запуска. Ошибка остановки не считается успешной передачей. Если управление внешним runtime не поддерживается, доступны просмотр и отдельное обсуждение; кнопка продолжения того же агента недоступна с объяснением.

### Совместная работа с кодом

В проекте видно, кто работает в какой папке / ветке. Для параллельной реализации используется существующий механизм worktree, когда он применим и выбран пользователем. Проверяются наличие репозитория, незакоммиченные изменения и фактический путь выполнения агента. Создание worktree само по себе не перенаправляет уже запущенного агента.

Работа пользователя с файлами остаётся доступной. Приложение обозначает активную работу в общей папке; не обещает исключительную блокировку файлов и не выполняет автоматические reset / checkout / merge / commit.

### Возврат результата

Связанная сессия предлагает подготовить комментарий и передать задачу на проверку. Завершение ответа модели не равно выполнению задачи; успешный выход процесса не равен принятию результата. Изменение статуса выполняется явно, подтверждается ответом Paperclip, а при ошибке черновик остаётся доступен.

## Порядок реализации

1. **Проект как общая точка входа.** Привязка существующих рабочих папок и проектов Paperclip, общий экран задач / сессий, переходы к имеющимся файлам и Git. Без автоматического перемещения данных, создания задач или запуска агентов. Несвязанные проекты и обычные сессии продолжают работать самостоятельно.
2. **Связи задач и диалогов.** Открытие обсуждения из задачи, привязка существующего диалога, черновик «Передать команде», навигация в обе стороны и явная отправка результата. Сохранять историю связи после перезапуска и не смешивать одинаковые projectId разных подключений / организаций.
3. **Передача выполнения.** Адаптер возможностей конкретного runtime: наблюдать, отправить уточнение, остановить, возобновить или создать новую связанную сессию. Возможности показываются по реальной поддержке. Конкурирующие действия разрешает владелец исполнения, а не только состояние кнопки в UI.
4. **Общий обзор работы.** Объединить представление активности и внимания по проектам с сохранением источника событий, раздельного учёта расходов и отсутствием двойного подсчёта связанных запусков.

Первый этап должен уже позволять открыть проект и приступить к своим правкам, одновременно видя работу команды. Замена всей архитектуры запуска на первом этапе не нужна.

## Проверяемые критерии

- Из одного проекта доступны его сессии, задачи и локальный код; задачи чужой организации или проекта не смешиваются.
- Одна задача с тремя запусками отображается как одна задача с историей, а не три дубликата работы.
- Открытие проекта, задачи или связанного диалога не запускает модель и не меняет назначение.
- Несвязанные сессии и проекты не требуют подключения Paperclip.
- Поздний ответ после переключения проекта не меняет открытый проект; черновики сохраняются.
- Сбой Paperclip показывает недоступность и не блокирует локальный чат / Git.
- Передача и возобновление не создают двух владельцев одного выполнения; неподдерживаемые действия не имитируются.
- Отсутствующий локальный каталог, удалённое выполнение и несовместимая runtime-сессия имеют явное объяснение и безопасный доступный следующий шаг.
- При отправке задачи или результата после неопределённого сетевого исхода не появляются незаметные дубликаты.
- Показатели использования не суммируют повторно один внешний запуск, показанный и в задаче, и в списке сессий.
